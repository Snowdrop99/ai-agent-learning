## 失败记录（今天真正学到东西的地方）

### 1. 分块器没兜住超长段落
- 现象：`mcp-intro` 3.5 万字符只切出 6 块，单块近 6000 字。
- 原因：`flush` 只在"加入下一段会超限"时触发，单段本身超限则永远不切。
- 修法：段落超长先按句末标点拆成"句原子"，极端情况硬切。
- 结果：165 → 279 块。**分块的第一个敌人不是 size 设错，是 size 根本没生效。**

### 2. overlap 切在单词中间
- 现象：块首大量 `tion:`、`ppings:`、`n"`。
- 原因：`buf[-overlap:]` 是硬切。
- 修法：overlap 尾巴向前对齐到最近的词/句边界。断词残片会污染 embedding，也让引用读起来像乱码。

### 3. 检索阈值拍脑袋 → 闸门失效
- 现象：`s2_failures.py` 第一条断言就挂了。"量子纠缠如何影响白酒板块估值"以 **0.44** 分蹭到一段 JS 垃圾，因为阈值是 0.30。
- 标定：8 个查询测 top1 分数 —— 相关题 0.500~0.568，无关题 0.218~0.391。取 **0.45**。
- 教训：**阈值要用负样本标定**。只拿好问题调参，永远发现不了闸门是坏的。

### 4. 引用校验被"元讨论"误伤
- 现象：模型第一轮编了个 `[S1]`，修复机制触发；但重写后的答案里有"上一条回复中的 `[S1]` 是我笔误"，校验器又把它判成无效引用。
- 原因：纯文本匹配分不清"引用"和"提到引用"。
- 修法：先把引号/反引号/「」里的内容剔掉再匹配；同时要求修复提示禁止复述被删编号。
- 教训：**校验器必须容忍模型谈论自己。** 这类 bug 只有让它在真实对话里跑才会暴露。

### 5. 同一批 URL 两次抓取结果不同
- 现象：`ingest.py --reset` 第一次 `openai` 403、`arxiv` 成功；第二次反过来。
- 应对：摄取做成幂等（按 `doc_id` 去重），失败只跳过不毒化索引，直接重跑即可补齐。

### 6. 正文抽取过滤太狠会伤召回
- 现象：加了代码残渣过滤器后，`mcp-intro` 从 34898 → 2288 字符。
- 原因：Mintlify 类文档站的正文在 JS payload 里，被当成代码整行丢弃。
- 结论：过滤器是"精度 vs 召回"的旋钮，不是纯收益。这类站点应该直接取 markdown 源。

## 今天的一个判断

`agent.py` 从 140 行长到约 400 行，**多出来的部分几乎全是"失败怎么办"**，不是"怎么变聪明"。这大概是 Stage 2 最想让人体会的：
